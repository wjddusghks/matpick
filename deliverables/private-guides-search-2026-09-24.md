# 관리자 전용 가이드의 맛픽 검색 연결

## 변경 내용

- 레드리본 지역 원형 버튼은 외부 네이버 목록 대신 맛픽 지도(`/map?type=private-guide&value=지역ID`)를 엽니다.
- 관리자 인증 후에만 별도 서버 자료를 읽습니다. 인증하지 않은 요청, 일반 회원, 다른 계정의 서명 토큰은 403으로 거절합니다.
- 관리자에게는 일반 검색·내 주변 검색·주소/메뉴 검색에서 같은 검색 함수와 거리 정렬을 적용합니다. 6개씩 더 보기도 유지합니다.
- 상호·주소·좌표가 일치하는 식당은 기존 공개 식당에 비공개 가이드 표시만 붙입니다. 다른 지점은 합치지 않습니다. 지정한 공개 식당 ID와 실제 지점이 다르면 보류합니다.
- 로그아웃·계정 변경·인증 만료 후 비공개 식당과 표시를 제거합니다. 지연 렌더링이 이전 데이터를 다시 보여주지 않도록 현재 권한의 목록과 대조합니다.
- 비공개 식당은 별도 관리자 상세 화면으로 연결합니다. 공개 찜/공유 저장, 최근 검색 저장, 검색엔진 구조화 데이터에 넣지 않습니다. 관리자 세션의 방문 추적도 제외합니다.
- 공개 식당 데이터·사이트맵에 비공개 레코드를 넣지 않습니다.

## 실제 데이터 상태

**레드리본 식당 등록 수는 0건입니다.** 공식 목록의 자동 수집·저장은 자동 승인 심사에서 거절됐습니다. 앞서 제공된 사전 서면 허가 없는 수집·복제 금지 안내가 이유입니다. 관리자 전용 노출로 설정해도 수집 권한을 얻은 것은 아닙니다. 허가가 확인될 때까지 수집을 진행하지 않았습니다.

따라서 이번 변경은 검색 연결과 접근 제어의 구현입니다. 실제 목록을 모두 채웠거나 운영 데이터로 검색 검증을 완료했다는 뜻은 아닙니다. 화면에 등록 대기 상태를 표시합니다.

## 후속 등록 방식

서버 전용 `api/admin/_privateGuideCatalog.json`에 이용 허가와 지점·좌표 검증이 끝난 항목만 넣습니다. 공개 데이터 생성 스크립트로 이 파일을 가져오면 안 됩니다. 데이터 이용 허가의 근거는 별도로 보관하며 API 응답에 개인정보나 계약서를 넣지 않습니다.

각 항목은 일반 Restaurant 필드(상호·주소·지역·분류·대표 메뉴·좌표·메뉴/가격 등)와 `privateGuideIds` 배열을 가집니다. 지역 ID는 `seoul`, `capital`, `gangwon-chungcheong`, `gyeongsang`, `jeolla`, `jeju`입니다. 새 식당 ID는 `private-guide:`로 시작합니다. 기존 식당에 연결할 때에는 `publicRestaurantId`를 함께 기록하고 주소와 좌표를 정확하게 대조합니다. 잘못된 기존 ID는 임의의 신규 식당으로 게시하지 않습니다.

비공개 식당의 직선거리는 공개 식당과 같은 방식으로 계산합니다. 현재 서버의 자동차 시간 API는 공개 식당 ID를 받으므로, 비공개 전용 식당의 자동차 길찾기는 카드의 네이버 길찾기 버튼으로 확인합니다. 기존 공개 식당과 합쳐진 경우에는 기존 자동차 시간 조회가 유지됩니다.

## 검증

- TypeScript 검사 통과
- 전체 테스트 137개 통과: 인증 차단, 동일 지점 병합, 다른 주소 분리, 명시적 연결 충돌 보류, 메뉴/지역/출처 검색, 6개 이후 결과 확장, 로그아웃 후 비공개 자료 제거 포함
- 테스트는 가상 식당 데이터로 실행했으며 운영 데이터에 넣지 않음
- Vite 배포 빌드 및 번들 제한 검사 통과: entry 125,966 B / home 161,301 B / map 1,084,445 B (gzip)
- 로컬 브라우저에서 비로그인 접근 제한과 기존 성수 검색의 결과/지도/더 보기 표시 확인
