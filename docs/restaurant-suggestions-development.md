# 식당 제보 로컬 점검

## 변경 배경

Vite 개발 서버는 Vercel API 함수를 실행하지 않아 `/api/restaurants?scope=suggestions` 요청에 SPA HTML을 반환했다. 프런트엔드는 JSON 접수 번호를 받지 못해 접수 실패를 표시했다.

## 로컬 실행

`matpick_all`에서 기존 `pnpm dev`로 실행한다. 개발 전용 Vite 플러그인이 제보 API만 연결하며, 저장소는 `matpick_all/.local-data/restaurant-suggestions.json`이다. 실제 파일 저장이 성공해야 `storage: local` 접수 번호를 반환한다. 이 파일은 Git에서 제외되며 Vite 정적 파일로 제공되지 않는다. 로컬 접수는 운영 사이트에 전송되지 않고 화면에도 이를 알린다.

같은 requestId 재요청은 기존 접수 번호를 반환한다. 입력 내용이 다르면 충돌로 처리한다. 로컬 보관 기간은 180일이며 다음 저장소 작업에서 만료 항목을 정리한다. 목록·상태 변경에는 기존 서명된 관리자 인증이 계속 필요하다. 관리자 인증 API 전체를 개발 서버에 연결한 것은 아니다.

## 운영 배포

운영은 기존 Redis 저장소를 사용한다. `KV_REST_API_URL`과 `KV_REST_API_TOKEN` 또는 기존 Upstash 환경 변수가 필요하다. 개발 파일 저장소는 Vite serve에만 적용되며 Vercel 함수로 배포되지 않는다. 운영 제보 기능은 프런트엔드와 `/api/restaurants` 함수를 함께 배포해야 한다. 이번 작업에서는 운영 배포를 실행하지 않았다.

## 주소 검색

기존 NAVER Maps 공개 키의 Geocoder 모듈을 사용한다. 입력 중에는 호출하지 않고 주소 검색 버튼·Enter에서만 검색한다. 같은 페이지에서 동일 검색어 결과 50개까지 캐시하고 동시 중복 요청도 합친다. 도로명 또는 지번을 선택하면 주소 입력란을 채우며 층·호수는 별도 선택 입력으로 저장한다. 검색 실패 시 직접 입력과 재시도가 가능하다.

## 검증 기록

- 주소 검색 → 도로명 선택 → 상세주소 → 메뉴·가격 → 접수 번호 반환을 로컬 브라우저/HTTP에서 확인.
- 실제 파일 저장·재시도·저장 실패·관리자/출처 검사·주소 정규화·초안 복원 등 관련 테스트 29개 통과.
- TypeScript 검사, Vite 빌드 및 번들 크기 검사 통과.
- 테스트 접수 2건은 `[검수용]`으로 표시해 archived 상태로 보관.
- 모바일용 CSS는 포함했으나 브라우저 뷰포트 변경이 적용되지 않아 실제 모바일 크기 화면 검증은 완료하지 못함.
