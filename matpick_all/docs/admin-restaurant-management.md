# 식당·메뉴·가격 관리

`/admin`의 **식당 · 메뉴 · 가격 관리**에서 `/admin/restaurants`로 이동한다. 등록된 관리자 계정만 사용하며 서버가 기존 서명 로그인 토큰과 관리자 허용 목록을 모두 확인한다.

식당명·주소·메뉴 검색, 주제별 필터, 메뉴 없음·가격 없음·관리자 수정 필터를 제공한다. 식당 정보·좌표·영업 상태와 메뉴 추가/삭제, 가격·대표 메뉴·확인일·출처를 편집할 수 있다. 미확인 가격은 빈칸으로 둔다. 휴업·폐업·이전 식당은 기존 추천 제외 규칙을 따른다.

## 폐업 식당 삭제·복구

편집 화면 상단의 **식당 삭제**에서 상호·주소를 확인하고 삭제한다. 저장된 `deletedAt` 표시를 적용해 공개 카탈로그에서 제외하므로 검색·지도·상세 화면에 나오지 않는다. **삭제된 식당** 목록에서는 마지막 저장 정보와 함께 확인하고 **식당 복구**할 수 있다. 삭제 직전 저장하지 않은 편집은 버리며, 저장된 메뉴·주소·가격과 영업 상태는 복구를 위해 유지한다. 복구 후 영업 상태가 폐업이면 기본정보에서 따로 정정해야 추천 대상이 된다. 삭제·복구도 서버 관리자 인증, 버전 충돌 검사, 비공개 변경 이력을 사용한다. 삭제된 상태에서는 일반 저장·원본 초기화를 차단한다.

## 네이버 메뉴 붙여넣기

**여러 메뉴 추가**에 메뉴 영역만 복사한다. `메뉴명\n9,000원`, `메뉴명 9,000원`, 엑셀 메뉴명·가격 두 열을 읽고 대표·인기 표시와 같은 안내 문구를 제외한다. 같은 이름·가격의 중복은 건너뛴다. 미리보기에서 전체 결과를 확인하고 추가한 뒤 **변경사항 저장**을 눌러야 반영된다. 설명·수량 등 여러 줄 때문에 어느 메뉴의 가격인지 불분명하면 해당 행을 표시하고 추가를 막는다. 안내된 설명 줄을 지우고 다시 확인한다. 이미지 속 글자를 읽는 OCR 기능은 아니며, 가격 출처와 확인일은 출처·메모 탭에 별도로 기록한다.

## 주소로 위도·경도 입력

**기본정보 → 주소 → 주소·좌표 찾기**에서 도로명·건물번호 또는 지번으로 조회한 뒤 **주소·좌표 적용**을 누른다. 선택한 주소와 NAVER WGS84 좌표를 함께 입력한다(`y`=위도, `x`=경도). 층·호수는 적용 후 주소 끝에 덧붙일 수 있다. 변경사항 저장 전까지는 초안이며, 조회 실패·결과 없음·좌표 누락은 기존 좌표를 지우지 않는다. 주소 수정이나 식당 전환으로 지난 요청이 늦게 완료돼도 다른 식당에 적용하지 않는다. 주소·좌표 수정 시 이전 위치 검증일·출처를 비워 오래된 검증이 새 위치에 붙지 않게 한다.

조회는 버튼을 눌렀을 때만 수행하고 기존 주소 검색 캐시(세션 내 최대 50개)·동시 요청 합치기를 재사용한다. 새 API 키나 서버 함수는 추가하지 않는다. NAVER Maps 애플리케이션에 현재 접속 URL과 Geocoding 사용 설정이 필요하다. 로컬 검수에는 기존 허용 URL `http://localhost:3000`을 사용한다. 임의의 미리보기 포트에서는 인증 오류가 날 수 있다. 좌표 필드 정의: [NAVER 공식 Geocoding 문서](https://api.ncloud-docs.com/docs/application-maps-geocoding).

저장은 기존 Redis/KV 연결(`KV_REST_API_URL` + `KV_REST_API_TOKEN` 또는 Upstash 동등 설정)을 사용한다. 연결되지 않았을 때는 조회만 제공하고 저장 성공으로 표시하지 않는다. 수집 원본 JSON은 변경하지 않으며 `matpick:restaurant-edits:v1` 해시에 공개 수정 사항을 저장한다. 재배포 시에도 수정 사항이 우선한다. 원본 복원은 삭제가 아니라 수정 내용을 비우는 새 버전이며, 최근 500개 변경 이력을 별도 비공개 키에 보관한다.

동일 식당은 버전을 비교해 원자적으로 갱신한다. 다른 창이 먼저 저장하면 409 오류로 알려주고 덮어쓰지 않는다. 관리자 식별자는 공개 API에 포함하지 않는다.

웹 앱은 카탈로그 페이지를 처음 열 때 `/api/restaurants`를 한 번 읽고 검색 색인·지도·상세 데이터를 생성하기 전에 수정 내용을 적용한다. 저장 후에는 해당 식당의 편집 페이지를 다시 불러와 버전을 맞춘다. 이미 열려 있는 다른 브라우저 탭은 새로고침해야 변경이 보인다. 공용 API가 일시적으로 실패하면 배포 파일의 카탈로그로 동작한다.

검색엔진용 정적 사전 렌더링 문서는 배포 시 생성한 자료다. 관리자 변경은 방문자가 보는 앱에 적용되며, 정적 HTML을 실시간으로 재생성하는 범위는 포함하지 않는다. 새 식당·소개 주제 추가는 기존 수집·검수 파이프라인을 사용한다.
