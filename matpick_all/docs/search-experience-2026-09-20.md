# 검색 화면 개선 및 길찾기 연결

## 반영한 동작

- 검색 화면의 왼쪽 관련 주제 레일과 모바일의 큰 프로그램 이미지 띠 제거. 데스크톱 목록 폭 420px, 남은 공간은 지도에 사용.
- 식당마다 방송 소개·영상 소개·가이드 수록 배지를 표시. 마우스 호버, 클릭, 키보드 Enter/Space, 모바일 탭으로 설명을 볼 수 있음. 미쉐린 수록을 스타 획득으로 표현하지 않음.
- 목록은 처음 6개, 더 보기로 6개씩 추가. 위치 권한이 있으면 모든 검색 결과를 현재 위치의 **직선거리** 순으로 정렬. 도로 거리나 이동 시간으로 정렬했다고 표시하지 않음. 좌표 없는 식당은 뒤로, 위치가 없으면 기존 검색 순서 유지.
- 위치 새로고침을 눌러도 검색 지역은 유지. 기존 위치 요청 취소·오차·권한 거절 처리 유지.
- 공유 버튼은 항상 공유창을 열고, 정식 matpick.co.kr 식당 주소를 제공. 기본 공유 실패 시 복사 버튼 사용 가능. Clipboard API가 없거나 막히면 선택 기반 복사, 그것도 실패하면 링크를 직접 선택하도록 안내.
- 기존 상세 화면의 공유에도 같은 공유창 적용.
- 개인정보 안내에 경로 조회 시 NAVER Maps·ODsay에 출발지와 식당 좌표가 전달되는 실제 동작을 한국어·영어로 설명.

## 이동 거리·시간

- 처음 6개 식당의 자동차와 대중교통 경로를 각각 조회. 자동차는 NAVER Maps Directions 5의 실시간 빠른 길, 대중교통은 ODsay의 도시 내 전체 경로 중 가장 짧은 시간.
- 네이버 duration은 밀리초 → 분, ODsay totalTime은 분. 전체 경로 거리만 m/km로 표시. 직선거리로 시간을 추정하지 않음.
- 위치·검색 변경 시 이전 요청을 취소. 페이지 메모리에서 최대 5개 검색을 캐시하며 재사용 유효기간은 3분. 주기적인 자동 API 호출 없음.
- 인증 미설정·조회 실패·지원하지 않는 경로는 시간이 표시되지 않으며, 출발지와 식당 좌표 및 car/traffic 이동수단이 지정된 카카오맵 링크를 제공.
- ODsay 도시 간 응답은 터미널 접근·도착 후 식당까지 구간이 빠질 수 있으므로 전체 소요 시간으로 표시하지 않음. 이 경우 지도에서 확인.
- 서버는 실제 공개 식당 ID 최대 6개만 허용. 임의 목적지, 추천 보류·휴폐업 식당, 잘못된 좌표를 거부. same-origin, IP 분당 제한, 공유 일일 요청 제한, 타임아웃 적용. 좌표·비밀키·원본 경로 응답을 서버 로그나 분석 이벤트에 기록하지 않음.

## 현재 연결 상태

2026-09-20 네이버 콘솔에서 맛픽 애플리케이션의 Directions 5 활성화 확인. 로컬 환경에는 지도 표시용 ID만 있음. 자동차 경로용 서버 비밀키를 아직 등록하지 않았으며 실제 경로 조회도 미검증.

사용자는 ODsay 계정·키가 없다고 응답. 따라서 대중교통 숫자 표시는 아직 활성화하지 않음. 로컬 코드·테스트 완료와 운영 배포·API 활성화는 별도 상태임.

## ODsay 설정 순서 (Vercel에서는 Web 방식)

1. [ODsay LAB](https://lab.odsay.com/)에 로그인하거나 가입.
2. 애플리케이션 등록에서 웹(Web/URI) 플랫폼을 선택하고 `https://matpick.co.kr`을 서비스 주소로 등록. 다른 도메인에서도 직접 서비스한다면 그 주소도 추가. 개발 주소는 실제 테스트할 때만 등록.
3. 대중교통 길찾기 `searchPubTransPathT`를 사용할 수 있는 서비스와 호출 한도를 확인하고 **Web API Key** 발급.
4. Vercel의 기존 맛픽 프로젝트 → Settings → Environment Variables에 `VITE_ODSAY_WEB_API_KEY` 등록. Production 및 필요한 Preview 환경 선택.
5. 빌드에 들어가는 값이므로 재배포. 위치 허용 후 식당 6개의 대중교통 분/km 표시를 확인.

Web 키는 브라우저에서 사용하도록 발급된 키이며 도메인 제한이 필수. Server 키를 이 변수에 넣지 않음. Server 방식은 `ODSAY_API_KEY`와 ODsay에 등록된 출구 IP가 필요하므로, 기본 Vercel 서버의 동적 출구 IP에 Web 키를 대신 넣어 해결할 수 없음.

## 자동차 설정

네이버 클라우드 Maps → 맛픽 → 인증 정보의 **새 Maps 서비스 API Key**를 Vercel 서버 변수 `NAVER_MAP_API_KEY`에 등록. 필요 시 같은 애플리케이션의 ID를 `NAVER_MAP_API_KEY_ID`에 등록하며, 생략하면 기존 `VITE_NAVER_MAP_KEY_ID` 사용. 기존 서버 변수 `NAVER_MAP_CLIENT_SECRET`도 호환하지만 네이버 로그인용 secret과는 다른 값.

비밀키에는 `VITE_` 접두사를 붙이지 않음. 운영에서는 기존 KV 저장소가 연결되어 있어야 일일 요청 제한이 여러 서버 인스턴스에서 공유됨. 기본 `ROUTE_DAILY_REQUEST_LIMIT=300`은 최대 6개 식당을 담은 배치 요청 수 제한이며, 네이버 콘솔 자체 호출 한도도 유지해야 함. API 사용 요금·한도 선택은 콘솔에서 확인.

## 확인

- TypeScript 검사, 검색·공유·경로 변환·데이터·후기 관련 23개 테스트 통과.
- 모바일 실화면에서 6개 결과, 프로그램 설명, 공유창, 복사 성공 안내 확인.
- 실제 390px 모바일 및 1280px 데스크톱 화면에서 가로 넘침 없이 표시. localhost:3000에서 지도 정상 표시. 127.0.0.1:3002 별도 주소에서는 지도 로딩 실패하므로 개발 시 등록된 localhost 주소를 사용.
- 프로덕션 빌드, 번들 크기 검사 및 2,907개 식당 SEO 사전 렌더링 통과.
- 외부 SNS에 실제 게시하거나 실사용자 후기를 작성하지 않음.
- 실제 API 시간은 키 등록 후 공개 출발점·식당 좌표로 먼저 검증할 것.
